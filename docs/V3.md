# Live H3 Chat v3

v3 turns the prototype into an app-owned H3 FL2VA runtime instead of a collection of manually synchronized node IDs.

## One-time workflow adoption

Build/test the underlying H3 + LLM graph in ComfyUI, export API JSON once, paste it into Setup, then click **Adopt workflow**.

The importer discovers semantic roles from graph structure:

- `MiniMaxH3ImageToVideo` is the FL core.
- The nodes connected to `first_frame` and `last_frame` are the dynamic continuity/canonical image loaders.
- `Live H3 Trace Text` with label `director_input` marks the LLM input boundary.
- `Live H3 Trace Text` with label `llm_output` marks the LLM output boundary.
- `Live H3 Trace Text` with label `final_h3_prompt` is optional in v3.
- The terminal video save/combine node is discovered structurally.

The saved contract contains selectors such as class type, trace label, title, and input signature—not numeric node IDs. Renumbering the workflow therefore does not require remapping the app.

The canonical API workflow is persisted by the app and becomes the source template for every runtime job.

## Two-phase showrunner

Chat and occasional proactive idle beats execute as two separate Comfy jobs:

1. **Director preflight**
   - The app clones the canonical workflow.
   - It injects `LiveH3ShowrunnerOutput` after the `llm_output` trace.
   - It prunes the clone to only that dependency graph.
   - The LLM returns structured JSON: dialogue, action, tone, beat, return-to-neutral, and estimated spoken duration.
2. **Video job**
   - The app builds the final H3 prompt deterministically from that JSON.
   - It writes the final prompt directly into H3, so the LLM branch is not executed a second time.
   - FL continuity, frame length, seeds, and governor tunings are applied.

Normal silent idle clips skip the LLM entirely.

## Smart cancellation

When new chat arrives:

- unplayed future FL clips are flushed;
- continuity rewinds to the currently playing clip's actual extracted last frame;
- if an obsolete idle/director job is early enough in its estimated runtime, the app sends a targeted ComfyUI `/interrupt` for that prompt ID;
- if the job is nearly done, it is allowed to finish but its result is discarded rather than corrupting the FL timeline.

The cutoff is configurable in Setup.

## Adaptive stream governor

The app tracks real-time factor (RTF):

`RTF = video workflow seconds / generated video seconds`

The governor uses an EWMA of recent RTF to:

- expand the target safety buffer when throughput gets tight;
- shorten chat clips toward the 124-frame minimum when latency matters;
- optionally use longer clips when there is substantial performance headroom;
- reduce numeric `steps` inputs only when RTF crosses the quality/latency threshold;
- never increase steps beyond the adopted workflow baseline.

The **Latency ↔ Quality** control changes how aggressively the governor sacrifices steps/latency.

## Creative idle beat engine

Setup contains an editable list of allowed idle actions. The runtime avoids recently used beats and injects a selected beat into each idle prompt.

A configurable fraction of post-prefill idle clips become **proactive idle** clips. Those go through the structured showrunner, allowing a short spoken or narratively meaningful moment rather than endless paper-shuffling.

## FL continuity and resets

This remains a single H3 FL2VA architecture:

- first clip first frame = canonical image
- every next clip first frame = actual extracted final frame of previous clip
- reset clip first frame = current chain frame
- reset clip last frame = original canonical image

No Ref2VA model switch is used.

## Required graph markers

For v3 adoption, the exported workflow should contain:

- exactly one `MiniMaxH3ImageToVideo` node;
- both its `first_frame` and `last_frame` inputs connected to Load Image nodes;
- `Live H3 Trace Text` labeled `director_input` before the LLM;
- `Live H3 Trace Text` labeled `llm_output` after the LLM;
- a normal terminal video saver/combine node.

`final_h3_prompt` tracing is now optional because v3 constructs and records the exact final H3 prompt itself.
